# Roadmap Spec — Slack Socket Mode (v1.7)

**Date:** 2026-08-06
**Issue:** [#13](https://github.com/hackeshackes/deerfllow-BY/issues/13)
**Status:** backlog — grooming only, no implementation this iteration

## Problem

The current Slack integration is webhook-based: Slack POSTs events to a public inbound URL. Deployments behind a strict firewall or with no public inbound port cannot use it. Socket Mode avoids the public URL entirely by opening an **outbound-only** WebSocket from the connector to Slack. Issue #13 was deferred from v1.6.1 → v1.6.2 → v1.7.

## Goals

- `SlackConnector.start_socket_mode(app_token, bot_token)` — opens `apps.connections.open` WebSocket.
- Reconnect with exponential backoff + jitter; no message loss across a disconnect.
- Frame dispatch reuses the existing `event_callback` → `ConnectorMessage` translation.
- Admin UI toggle: webhook vs socket mode (mutually exclusive).
- Document the tradeoff in `docs/connectors/slack.md`.

## Non-goals

- URL-verification handshake in Socket Mode (never received).
- Multi-socket fan-out or horizontal scaling of the socket in v1.7.
- Changing the outbound `send()` path (works the same in both modes).

## Proposed shape

- New module `connectors/slack/socket_mode.py` hosting the WS client + reconnect loop.
- Reuse `slack-sdk` (already a backend dep) for the WebSocket client.
- Config: add a `mode` field under the Slack channel config. **Backward-compat**: missing `mode` defaults to `webhook`.
- Reconnect: exponential backoff + jitter, capped; track reconnect count + 429s as metrics.

## Acceptance criteria

- [ ] Closed-network test: bot functions with **no inbound port** (outbound-only).
- [ ] Reconnect: kill the WS, reconnect within 5s, no message loss across a 30s test.
- [ ] Mixed-mode: webhook + socket both active (separate workspaces) with no cross-talk.
- [ ] Observability: 429 / reconnect count surface as metrics.
- [ ] Admin UI toggle: webhook ⇄ socket, mutually exclusive.

## Affected files (reference)

- `app/gateway/connectors/slack/{connector.py,socket_mode.py}`
- `config.yaml` → `channels.slack.mode`
- `docs/connectors/slack.md`
- Admin UI toggle in the channel config surface

## Open questions

- Reconnect window guarantee (5s target) vs Slack's backoff guidance for rapid failures.
- Whether to pin the socket to a single channel service process or allow per-workspace.
