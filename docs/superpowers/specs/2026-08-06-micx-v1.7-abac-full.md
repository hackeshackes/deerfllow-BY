# Roadmap Spec — Full ABAC (v1.7)

**Date:** 2026-08-06
**Issue:** [#10](https://github.com/hackeshackes/deerfllow-BY/issues/10)
**:Status:** backlog — grooming only, no implementation in this iteration

## Problem

Authorization today is a mix of inlined `role == "owner"` RBAC checks scattered across routers and a small ABAC subset. Adding a new protected endpoint means hand-writing another role check, invites drift, and gives operators no visibility into policy. Issue #10 defers the full ABAC vision to v1.7.

## Goals

- A declarative **ABAC policies file** (JSON/YAML) that an operator can read, edit, and hot-reload without restarting the gateway.
- **Universal route coverage**: thread / workflow / connector / quota endpoints gated through ABAC, replacing inlined `role == "owner"` checks.
- An **owner-only frontend policy editor** with list / edit / diff-preview / publish and an audit trail of who changed what.
- **Backward compatibility**: existing RBAC paths keep working; ABAC is adopted gradually.

## Non-goals

- Reworking the identity/auth provider or the user model.
- Removing RBAC entirely in v1.7.
- Multi-tenant policy namespace isolation beyond what exists.

## Proposed shape

### ABAC policies file

```
backend/app/gateway/abac/policies.*.yaml    # authored presets
backend/.deer-flow/policies.json            # operator-edited overrides (gitignored)
```

- Schema: `{ policies: [ { id, effect: allow|deny, subject, action, resource, when } ], version }`
- Loaded at startup; **reload** on file change (SIGHUP or inotify/mtime poll, mirroring the existing config-mtime pattern).
- Evaluator stays a fixed AST (`equals`/`in`/`all_of`/`any_of`, `subject.workspaces` path); no `eval`/`exec` — reuse `abac/evaluator.py`.

### Universal coverage

- Reuse `evaluator.py` + `policies.py`; expand the set of `must_*` dependencies applied to routers: thread, workflow, connector, quota.
- Precedence: explicit `deny` > `allow` > lack of match (deny-by-default where a route is gated).

### Frontend editor

- Owner-only page under `admin-page-shell`: list policies, edit (JSON/YAML w/ codemirror), diff preview, publish (POST), and an audit readout from `audit.jsonl` `abac.*` events.

### Migration

- Script that scans router `role == "owner"` usage and emits an ABAC policy file entry (one-off, operator-run).

## Acceptance criteria

- [ ] Policy file format documented (`docs/abac/policy-spec.md`) with the `id/effect/subject/action/resource` schema.
- [ ] Hot-reload confirmed (SIGHUP or mtime + cache invalidation).
- [ ] Admin / audit / scim / upload / thread routes gated via ABAC.
- [ ] Frontend editor: list / edit / diff / publish; audit trail visible.
- [ ] Migration script promotes current `role == "owner"` checks into ABAC policies.
- [ ] Backward-compat: existing RBAC behavior unchanged until policies are introduced.

## Affected files (reference)

- `backend/app/gateway/abac/{evaluator,policies}.py`
- Routers: `collaboration/routers/publish.py`, `canvas/routers/workflows.py`, plus threads / connectors / quota
- `frontend/src/components/workspace/admin/` policy editor page
- `scripts/` migration tool

## Open questions

- Hot-reload trigger preference (SIGHUP vs inotify) given local filesystem + docker sandbox both in play.
- Whether the policies file should be per-workspace or global at v1.7 scope.
